# Save migration and portable state

**Historical execution record:** One-time recovery is complete. The in-game upgrade flow and
legacy engine have since been retired; their exact sources, fixtures and tools are archived in
`tools/archive/save-recovery-2026-10-23/`. Active snapshot compatibility and background autosaves
follow spec §21. Converted saves and original backups are preserved.

## Contract

Existing rules-6/7 saves must continue with batteries without changing their historical progress.
Verify the old format, checksum and exact region first. Replay through a frozen matching engine,
including the rules-6 black-start behavior, and require the original command count, Debug hash and
phase/date/status boundary. Export every mutable domain field and every projection into explicit
portable schema-1 mementos; import and re-encode them byte-for-byte before exposing a candidate.
Preserve cash/ledger, assets and construction instalments, grid and commitments, hydro plans and
budget, regulator/strikes/rate base, IDs, complete RNG seed/position, reports, milestones and charts.
The only additive content change is the frozen battery catalog entry; existing authored tuning
comes from the save, never the currently shipped region. New rules apply to future play.

Original slots are never overwritten by migration. Explicit Load/Resume atomically publishes a
separate, stable destination, with source slot/revision/rules/hash/count provenance. Retrying is
idempotent and confirms uncertain durability. Reject stale sources, cancellation and destination
collisions. Candidate preparation and opening-screen preload remain read-only. Hide an unchanged
original from the library only while its checksummed upgraded copy exists; deleting/corrupting the
copy or changing the original makes the original visible again. Keep archived originals on disk.

## Future storage policy

Save envelope version 2 stores complete, compressed domain and projection snapshots plus the
accepted-command audit trail and original region. Portable schema versions are independent of
simulation-rule versions. Explicit field order, little-endian scalars and enum tags replace Rust
Debug as the persisted state representation; Debug hashes remain only for old-format verification.
A portable restore does not rerun historical economic or simulation decisions. SHA-256 protects
the envelope; bounded decoding, scalar validation, topology/ID checks, session invariants, canonical
re-encoding, journal hash and boundary checks protect installation. Preserve arbitrary mid-day
boundaries and pause on resume.

Keep schema-1 readers and golden historical saves. A future field/enum change must explicitly
supply a backward-compatible default or add a schema upcaster, and CI must load and continue all
supported fixtures. Rule bumps alone must not invalidate snapshot saves. This still requires
migration work for genuinely changed data semantics; it removes the need to retain a whole engine
for each new feature. Never silently reprice history, discard unknown state, erase originals or
prune progress to make a save fit. Unsupported future formats fail without writing anything.

Snapshot-rooted diagnostic recordings use log format 2 with a verified checkpoint sidecar and
an explicit replay API. Command-only replay rejects that format instead of ignoring its base.
Ordinary format-1 logs and rules-8 command-only saves retain their original reader.

## Follow-up: retire pre-release recovery and background autosave

The shipped game no longer contains legacy-sim, frozen migration tuning, Upgrade-and-resume UI
or migration publication on activation. The exact recovery workspace and its nine passing
migration tests are preserved in the checksummed source archive under
`tools/archive/save-recovery-2026-10-23/`. Extracted source hashes and an isolated rebuild verified
the archive. Released portable schema fixtures and automatic future schema compatibility remain
active; snapshot provenance still protects originals and suppresses exact duplicates.

Monthly autosaves now write immutable closing snapshots in the background without showing a
modal or freezing Review/Continue. A single writer serializes queued months and resolves revision
checks after receipts; completion cannot pause later play or close a manual dialog. Failure alone
opens the existing retry/continue barrier. Delayed-worker tests cover later play, queued boundaries,
retry with newer captures pending and cancellation of an independent manual dialog.

Validation: 1,317 workspace tests passed; archived recovery tests passed separately (9/9). Clippy,
formatting, build, doctests and the 120-frame native smoke passed. An isolated native playtest
loaded the existing February 2033 snapshot via ordinary Resume, played March at 32×, confirmed
the unobscured monthly review and saved status, and opened the retrospective. All 74 existing
player save/backup/manifest files remained byte-identical.

The read-only `verify_saves` example restored all 25 visible snapshots using the shipped loader
after engine removal, including the player's newer April 2033 boundary (76 reports and 10,700
accepted commands). Complete checkpoint comparisons passed; no player files were written.

## Follow-up: fast save-library metadata

Listing now extracts card metadata without constructing terrain, sessions or command histories.
A per-store memory cache reuses unchanged rows across menu transitions and refreshes only changed
files; no sidecars or save rewrites are needed. File identity/timestamps invalidate external edits,
including same-size edits with restored mtime on Unix. Atomic-read races and transient I/O errors
are not cached. Selected loads always validate fresh bytes through the complete reader/restore.
Cached cards paint immediately while metadata refreshes; selected loading retains its separate
restoration progress message.

Measured with the 25 visible player saves in a debug build: scans previously took 5.88 seconds
cold and 5.90 seconds repeated. The new path took 1.286 seconds cold and 295 microseconds cached.
The full suite passed 1,328 tests; 54 UI/localisation tests were rechecked after final progress-label
polish. Clippy, formatting, build, doctests and native smoke passed. Native QA opened the copied
library and loaded the April 2033 game normally. Read-only verification restored all 25 snapshots,

### Follow-up: complete Resume preparation and persistent metadata index

individual historical-command writes until Resume. Preparation now captures an immutable
`PendingRecording` and encodes/compresses its exact diagnostic base in memory. Activation rechecks
the source revision and publishes a fresh recording with batched prefix writes; other menu choices
and cancellation drop the prepared memory without speculative recording files or simulation state.
Prepared bytes are checked against the entire captured checkpoint before writing.

The lightweight store cache now persists atomically in a bounded, checksummed, versioned
`.save-library-cache.ron`, tied to the inspecting build/platform. Restarts enumerate the directory
and stat every source before reuse. Stable unavailable-card errors and exact conversion provenance
are retained, while transient read failures and raced reads are retried. Missing/corrupt/obsolete/
unwritable indexes fall back to source metadata scanning; selected loading still decodes and
verifies fresh source bytes. No player save format or original backup changed.

### Follow-up: lossless tick journal RLE

New save envelope 3 encodes only adjacent identical tick batches as `TickRun(n,repeat)`, retaining
ordinary commands as `Command(CommandDto)`. Readers still accept original formats 1 and 2. Expand
every run into its exact original commands before count/audit-hash validation, diagnostic-prefix
comparison or command-only replay. Zero ticks, speed changes, player actions and projection batch
boundaries are preserved. Portable schema, simulation rules, diagnostic log/live append formats and
atomic save publication remain unchanged. Runs are length-checked before expanded allocation,
bounded by the original command cap and cancellable; empty/malformed/overflowing/mismatched runs fail.
Existing player games are not rewritten automatically.

The latest April 2033 snapshot is 12,735,537 bytes (12.15 MiB; 12,738,560 allocated bytes). Its on-file
components are 12,435,308 bytes of chart/report projections (97.643%), 46,962 bytes of session state,
38,537 bytes of exact archived region, 213,666 bytes of journal field and 1,064 bytes of other
metadata/framing/checksums. These component counts include field keys; projection/session values
are already zlib-compressed but represented as decimal RON byte arrays. Their compressed binary
sizes are 3,492,244 and 13,063 bytes respectively. The journal's value alone shrinks from 213,657 to
32,282 bytes with RLE: 10,311 tick commands become 77 runs, retaining all 10,700 expanded commands.
Re-encoding the complete snapshot in memory produces 12,554,163 bytes, a 181,374-byte (1.424%) saving.

### Follow-up: monthly binary chart directories

Store each new player snapshot in `<slot>.mgsave/`. `snapshot.ron.z` is a checksummed, compressed
text manifest containing game/summary/journal state and explicit monthly chart references. Each
`YYYY-MM-<SHA256>.bin.z` is compressed binary chart data for that month, with its size, expanded
size and digest bound by the manifest. Live chart buffers/forecasts are retained too. A pure
application decomposition reconstructs the exact canonical schema-1 projection bytes; simulation
rules, canonical hashes and tick RLE semantics do not change. No chart samples are discarded.

Publish immutable month files first, synchronise them and their directory, then atomically replace
the manifest. A new snapshot is prepared in a temporary directory and published as one directory.
Keep old referenced files until a durable manifest receipt; remove obsolete versions after success.
An uncertain receipt retains all referenced data for Retry. Delete renames the whole directory out
of the library before synchronising its disappearance and cleaning it up. Cached metadata checks
manifest and month-file identity/timestamps; full selected reads verify every named file, reject
path escapes/symlinks and restore the complete boundary. Diagnostic base checkpoints use the same
binary layout, avoiding decimal-array copies in Resume logs. Historical flat codecs remain readers,
not an automatic migration or upgrade UI.

As requested, run personal-save conversion once using local ignored tooling, validate reconstructed
checkpoints and progress before publication, retain the original library outside the repository,
and leave conversion out of the game. `/tools/archive/` is Git-ignored; neither its existing recovery
archive nor the new one-off converter, staged saves or receipts belong in Git. Preserve the user's
preferences and slot IDs, names, timestamps and original battery-migration provenance.
